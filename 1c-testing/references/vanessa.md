# Vanessa Automation и va-ai

## Роль Vanessa

Vanessa — второй уровень поверх YAxUnit. Используй её для пользовательских сценариев, форм, навигации, команд, UI-валидации и end-to-end цепочек.

Не заменяй YAxUnit UI-тестом, когда бизнес-логику можно быстро проверить на уровне BSL.

## Размещение

Не помещай `.feature` внутрь дерева метаданных тестового расширения, если оно целиком загружается Конфигуратором.

Рекомендуемая структура:

```text
features/
├── 00_Подготовка/
├── 10_НСИ/
├── 20_Продажи/
├── 30_Закупки/
├── 40_Склад/
├── 50_ВЕТИС/
├── 60_Доставка/
├── 70_Интеграции/
└── 80_EndToEnd/
```

Внутри блока:

```text
features/
└── 40_Склад/
    └── 01_ПеремещениеТоваров/
        ├── 01_Создание.feature
        ├── 02_Проведение.feature
        └── 03_КонтрольОстатков.feature
```

## v8-runner MCP — предпочтительно

Если MCP `v8_runner` доступен и Vanessa настроена в `v8project.yaml`, используй:

```text
run_all_tests
  runner: vanessa
```

При необходимости передавай только реальные параметры конфигурации:

- `profile`
- `feature`
- `filterTag`
- `ignoreTag`
- `scenarioFilter`

Не придумывай имена feature/profile/tag. Сначала читай `tests.va` в `v8project.yaml` и текущую структуру `features/`.

`v8_runner` отвечает за воспроизводимый запуск тестов. Для написания и интерактивной отладки сценария используй Vanessa MCP, если он доступен.

Если проект использует `v8-runner`, Vanessa MCP можно поднять тем же настроенным runner без отдельной ручной команды `1cv8`:

```powershell
v8-runner.exe --config <project>\v8project.yaml launch mcp va --wait-ready
```

Порт берётся из `tools.client_mcp.port`; URL Codex должен указывать на тот же порт и путь `/mcp`. Запуск меняет состояние тестового окружения, поэтому выполняй его только когда задача действительно требует Vanessa.

## Написание сценария через Vanessa MCP

Минимальный цикл:

1. Прочитать test-plan и найти близкие `.feature` проекта.
2. Получить состояние Vanessa и окружения доступными read-only инструментами.
3. Найти каждый нетривиальный шаг через `search_for_steps_by_keywords`; не придумывать формулировку шага.
4. Создать или изменить `.feature` в `features/<ФункциональныйБлок>/`.
5. Выполнить `check_syntax` для сохранённого файла.
6. Загрузить файл, запустить целевой сценарий и получить результат через доступные Vanessa MCP tools.
7. После успешной отладки выполнить воспроизводимый прогон через `v8_runner` и сохранить его evidence.

Названия конкретных MCP tools, кроме `search_for_steps_by_keywords` и `check_syntax`, сверяй с реально доступной схемой сервера: Vanessa развивается, поэтому не выдумывай параметры по этому документу.

Если Vanessa MCP недоступен, используй существующие feature проекта и встроенный каталог `vendor/va-ai`, описанный ниже. Не сочиняй шаги из памяти.

Отсутствие `.feature` не означает отсутствие Vanessa. Если EPF, профиль и тестовый клиент настроены, создай требуемый сценарий как часть задачи.

## CLI fallback

Если MCP недоступен:

```powershell
v8-runner.exe test va
```

Для специально подготовленной базы:

```powershell
v8-runner.exe test --no-build va
```

`--no-build` — CLI-only fallback; не делай его стандартным режимом разработки.

## Локальный fallback va-ai

В skill закреплён минимальный автономный набор из `Nikolay-Shirokov/va-ai`: руководство, шаблоны, библиотека готовых шагов, поиск и валидатор. Он работает без Vanessa MCP и сети.

Порядок fallback:

1. Найди близкие `.feature` проекта.
2. Найди формулировки нетривиальных шагов в локальном каталоге.
3. Создай или измени сценарий.
4. Проверь сценарий локальным валидатором.
5. Если тестовая Vanessa настроена, запусти suite через `v8_runner`; отсутствие MCP не запрещает CLI-запуск.

Из каталога skill выполни:

```powershell
python .\vendor\va-ai\tools\search-steps\search_steps.py `
  --query "нажать кнопку создать" --top 10 --format human

python .\vendor\va-ai\tools\validator\validate.py `
  "<путь-к-сценарию.feature>" --compact
```

Для поиска нескольких действий передай их одним batch-вызовом после `--query`. Не читай весь JSON в контекст: используй поисковый скрипт. При неоднозначном результате сверяйся с `vendor/va-ai/ai-knowledge/guide.md` и `templates.md`.

Локальная библиотека является снимком известной версии Vanessa, а не доказательством наличия шага в фактически запущенной обработке. Поэтому при восстановлении Vanessa MCP повтори `search_for_steps_by_keywords` и `check_syntax`. Если локальный валидатор не находит обязательный шаг, не придумывай замену: зафиксируй ограничение и запроси доступ к актуальной Vanessa.

При наличии Vanessa MCP он предпочтительнее статической библиотеки `va-ai`, потому что возвращает шаги и состояние фактически запущенной версии Vanessa. `va-ai` остаётся полезным offline fallback и дополнительным валидатором.

## Разделение ответственности

Для проведения `ПеремещениеТоваров` YAxUnit проверяет расчёты, остатки, движения и ошибки бизнес-логики. Vanessa проверяет, что пользователь создаёт документ, заполняет форму, проводит его и видит ожидаемый результат.

Не дублируй в Vanessa десятки низкоуровневых вариантов, уже покрытых YAxUnit.
