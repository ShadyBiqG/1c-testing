# Регрессионный workflow

## Цель

После исправления дефекта тест гарантирует, что конкретная ошибка не вернётся.

## Алгоритм

### 1. Зафиксировать контракт

Определи входные условия, действие, ожидаемый результат и чем дефект отличался от правильного поведения.

### 2. Выбрать владельца

Найди существующий функциональный тестовый модуль. Например ошибка расчёта веса перемещения принадлежит `Тест_Склад_Док_ПеремещениеТоваров_МО`.

Не создавай `Тест_ЕР12854`, если естественный функциональный владелец уже существует.

### 3. Назвать тест

Если номер задачи известен: `ЕР12854_ВесРассчитываетсяПоУпаковкам`. Если номера нет: `ВесРассчитываетсяПоУпаковкам`.

### 4. RED

Для bugfix желательно подтвердить падение нового теста на старой реализации.

Но RED нельзя получать ценой риска для незакоммиченных изменений пользователя.

Допустимо написать тест до fix, временно вернуть только свою доработку при полном контроле состояния либо использовать отдельный worktree/ветку.

Запрещено: `git restore .` на грязном дереве, удалять чужие изменения, массово чистить untracked-файлы, подменять RED искусственным исключением.

Если старое состояние безопасно не воспроизвести — пропусти доказательство RED и сообщи это.

Для запуска RED:

- если доступен MCP `v8_runner` — `run_module_tests(moduleName = <РеальныйМодуль>)`;
- иначе CLI fallback `v8-runner.exe test yaxunit module <РеальныйМодуль>`.

### 5. FIX

Внеси минимальную production-доработку.

### 6. GREEN

Предпочтительно через MCP:

```text
run_module_tests
  moduleName: <РеальныйМодуль>
```

CLI fallback:

```powershell
v8-runner.exe test yaxunit module <РеальныйМодуль>
```

Исправляй только подтверждённую причину FAIL.

Если сбой является MCP transport error, build error, `junit_empty`, `0 сценариев` или startup timeout, сначала устрани/классифицируй инфраструктурную проблему; не считай это RED бизнес-теста.

### 7. REGRESSION

Нужен полный YAxUnit-прогон, если изменён общий механизм многих подсистем, проведение/движения, публичный API общего модуля, несколько функциональных блоков либо пользователь требует полный прогон.

Предпочтительно:

```text
run_all_tests
  runner: yaxunit
```

CLI fallback:

```powershell
v8-runner.exe test yaxunit all
```

Для локального изолированного изменения достаточно узкого модуля, если другие правила проекта не требуют большего.

## Реальный FAIL

Реальный FAIL означает, что тест выполнялся и testcase имеет failed/error.

Не путай его с ошибкой build, `0 сценариев`, `junit_empty`, отсутствием базы, timeout запуска платформы или ошибкой MCP-транспорта.
