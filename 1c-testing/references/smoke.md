# Дымовой тест: состав, открытие объекта и повторный запуск

Читай при выборе или создании smoke. Уровень L1–L4 определяется в SKILL.md;
эта памятка не расширяет выбранный набор проверок.

## Минимальный состав

Для UI сначала предпочитай OneRPA QA MCP/TestClient. Если уже есть устойчивый Vanessa smoke, его можно переиспользовать.

1. Открыть ожидаемую форму; для документа/справочника — форму нового объекта.
2. Подтвердить ожидаемое окно/элемент и отсутствие `ui_errors`.
3. Если изменённое поведение требует одного действия — выполнить его и проверить конкретный результат.
4. Закрыть форму без лишней записи/проведения.
5. Сообщить точный scope smoke: открытие формы или конкретное действие, без заявления о непроверенных операциях.

Для L4 UI-fix новый `.feature` не обязателен, если QA MCP smoke воспроизводимо проверяет изменённый контракт. Vanessa добавляй, когда regression должен сохраняться и повторяться в будущем.

Заполнение полей, запись, проведение и создание НСИ ради них не нужны. Готовь
помощниками только зависимости, без которых сама форма не открывается. Если
открытие создаёт данные или меняет состояние, обеспечь очистку/восстановление
по [test-data.md](test-data.md), включая FAIL. Отсутствие исключения без явной
проверки ожидаемой формы и один build не подтверждают открытие.

Для серверного API используй короткий вызов YAxUnit с проверкой результата.
Если изменение относится к операции, которая при открытии не выполняется,
добавь адресную проверку этой операции по выбранному уровню.
Для L4 достаточно одного такого сценария. Не создавай отдельную задачу, агента,
подробный план или второй тест другого фреймворка ради обычной локальной правки.
Если smoke не проверяет изменённое поведение, адаптируй его либо выбери L3.

## Внешняя обработка EPF или внешний отчёт ERF

Определи актуальный собранный файл и его связь с проверяемыми исходниками.
Используй существующие профиль Vanessa и TestClient тестового стенда.
Подтверждённый в поставляемом каталоге шаг:

```gherkin
И я открываю внешнюю обработку или отчет "ИмяФайла" (Расширение)
```

Это шаблон одного шага, не готовый тест. Передай реальный путь, доступный клиенту
тестирования; проверь поддержку шага установленной версией Vanessa. Для этого
маршрута VAExtension должен быть установлен в ИБ клиента тестирования.
Затем внутри того же smoke проверь, что ожидаемая форма открылась без ошибки,
и закрой её без выполнения операции. Отдельный предварительный UI-прогон не обязателен;
диагностика формы нужна, если её контракт неизвестен или запуск выявил проблему.

Только для проверки самой операции выбери команду и входные данные; для отчёта —
параметры/отборы, формирование и конкретное ожидаемое значение результата.
Имена команд и элементов бери из проекта/формы, не подставляй универсальные.

Если проверяются регистрация в БСП, доступность команды или права, открывай через
этот пользовательский маршрут: прямое открытие файла их не проверяет. Подтверди,
что зарегистрирован именно проверяемый бинарник. Если VAExtension недоступен,
используй уже подтверждённый проектом сценарий открытия файла через интерфейс.
При отсутствии рабочего маршрута укажи NOT_RUN и препятствие; не подменяй UI
серверным вызовом и не меняй защитные настройки базы ради открытия.

## Объекты внутри конфигурации

Для встроенной обработки и отчёта в каталоге есть отдельные шаги:

```gherkin
Дано Я открываю основную форму обработки "Обработка1"
Дано Я открываю основную форму отчета "Отчет1"
```

Это альтернативные шаблоны. Подставь подтверждённое имя объекта метаданных,
а не синоним, и выбери один нужный шаг. Проверь доступность в версии проекта.
Не используй эти шаги для внешнего файла. Для smoke достаточно проверить
открытие ожидаемой формы без ошибки и закрыть её.

Для документа или элемента справочника smoke по умолчанию открывает форму нового
объекта проверенным маршрутом проекта, проверяет её появление без ошибки и закрывает
без записи. При необходимости используй форму списка и штатную команду создания.
Не заполняй обязательные поля, не записывай и не проводи объект ради этого smoke.
Не ищи существующую запись и не создавай записанный объект серверным помощником
только ради открытия формы. Помощники нужны лишь для зависимостей самого открытия.

Если изменение касается редактирования или поведения уже записанного объекта,
создай собственный тестовый объект и затем выполни нужное действие. Допустимо
подготовить его помощником и открыть по полученной навигационной ссылке шагом
`Дано Я открываю навигационную ссылку "Ссылка"`; не придумывай UUID. Smoke должен
проходить изменённый путь. Для навигации/прав используй соответствующую команду
интерфейса. Конкретные маршруты и шаги подтверди в проекте; не открывай все объекты
конфигурации для одной правки. Общий модуль без формы проверяй через YAxUnit.

## Где хранить и как повторять

- QA MCP/TestClient smoke не требует отдельного файла теста. Сохрани только достаточное evidence текущего запуска; если проверка должна регулярно повторяться, материализуй её как Vanessa regression.
- `.feature` — в каталоге выбранного профиля Vanessa из `v8project.yaml`, рядом
  с тестами соответствующего объекта. Один устойчивый smoke на пользовательский
  путь; расширяй существующий вместо файла на каждый номер задачи.
- YAxUnit — в существующем тестовом source-set и модуле функционального блока.
  Подготовка и очистка — в помощниках; тест содержит подготовку → действие →
  ожидания. Не переименовывай рабочие модули только ради общей схемы.
- Повторяющееся открытие/настройку формы выноси в существующую библиотеку экспортных
  сценариев при реальном повторном использовании; фабрики данных переиспользуй
  между тестами. Не создавай новую библиотеку для единственного шага.
- Контрольные входные файлы — в принятом каталоге fixtures/data проекта либо
  воспроизводимо получай из явно заданного источника. Коммерческие документы
  не публикуй. Локальный файл в `build/tmp` допустим для испытания, но такой тест
  нельзя объявлять переносимым в CI без воспроизводимого источника/обезличивания.
- Логи, скриншоты и отчёты — в каталоге результатов runner; не в общем skill.

После первого успешного запуска сохрани в существующей документации тестов или
конфигурации проекта короткий рецепт: объект и исходники/бинарник, профиль, путь
feature/имя теста, подготовка и очистка, точная проверенная команда или MCP-вызов
с поддержанным фильтром. Не придумывай ключи CLI и не создавай новый реестр,
если это уже выражено профилем и сценарием. Следующий агент использует рецепт;
повторное исследование нужно при изменении соответствующего контракта/версии.

Общие инструкции и примеры остаются в skill; пути стенда, реальные локаторы,
фикстуры и команды запуска конкретного объекта — в прикладном репозитории.

Источник требования VAExtension и возможностей открытия:
[документация Vanessa Automation](https://github.com/Pr-Mex/vanessa-automation/blob/develop/docs/VAExtension/VAExtension.md).
Шаги сверены с поставляемым offline-каталогом; это не подтверждает их выполнение
в конкретной ИБ. PASS устанавливается только по реальному целевому запуску.
